## 0. 適用範囲と不変条件

- 対象は `fsv_uxe3`（冷暖フリーUXE3）のみ。他シリーズの計算経路には影響させない。
- UXE3の基準径未検証警告（`calculateSystem`）と手動一律増径の停止は維持する。CI成功はメーカー仕様への適合証明ではない。
- `edgeSpec` は引き続き監査・表示用である。区間種別・容量基準・検証状態をユーザー宣言や保存値だけで `verified` に昇格させない（`auditUxE3PipeSegments` の既存の扱いを維持）。
- 既存データに区間属性がないことを理由に、ノードの親子関係だけから LM / LC〜LH / LO を推定し、公式選定済みにしてはならない。
- 実長は子ノードの `length` を唯一の正とする。`edgeSpec.lengthM` と並行して独立加算しない（データ契約案 §3 と同じ）。
- 対応範囲は現行マスターの 8〜20HP のまま。表4の 26〜48HP の値は転記照合済みの参考値であり、アプリの対応範囲を広げる根拠にはならない。

## 1. C1 経路（パス）モデル — LMは辺ではなく LA＋LB の経路

### 現状（engine.js）
- 各辺の実長は子ノードの `length` にあり、`processNodeSizing` が辺ごとに全長を1つの径で BOM（`totals.liquidPipes / highGasPipes / lowGasPipes / gasPipes`）へ加算する。
- `totals.totalLength` は全辺の実長の合計であり、最遠経路長でも液管総和長でもない。最遠経路・LM・ΔL・液管総和を計算する処理は存在しない。
- `auditUxE3PipeSegments` は辺単位の監査のみで、経路の概念はない。

### 必要な経路（PA-P900UXE3 図1・表1より）
| 経路 | 定義 | 判定・上限（表1） |
|---|---|---|
| LM（主管） | LA＋LB。LA＝室外第一分岐〜第一分岐、LB＝第一分岐〜次の分岐 | 実長 ≦80m。L1相当長＞90mで3管とも1ランク増径（脚注＊2）。＊2以外でLM＞50mのとき最初の50mの吸込・吐出管を1ランク増径（脚注＊3、排他的） |
| L1（最遠配管長） | 室外機〜最遠室内機の経路 | 実長 ≦150m、相当長 ≦175m |
| ΔL | 第一分岐からの最大長と最小長の差 | ≦40m |
| 液管総和長 | L1＋ℓ1＋ℓ2〜ℓ39＋ℓA＋ℓB＋LF＋LG＋LH（液管のみ） | ≦300m |
| 室外機側接続 | ℓA、ℓB＋LP、ℓC＋LO＋LP、ℓD＋LO＋LP | 各 ≦10m |
| 各分岐管 ℓ1〜ℓ40 | 各辺の実長 | 各 ≦30m |
| 高低差 H1・H2・H3 | 室外〜室内 ≦50m（上）／40m（下）、室内間 ≦15m、室外間 ≦4m | ツリーに高低差の入力が存在しないため、現行モデルでは判定不能（§8参照） |

### 設計案
- 経路は辺の集合として**導出**する。辺に経路IDを保存するのではなく、ツリーの走査から経路レコードを生成する（監査出力としてまず非破壊で出す。データ契約案 §4 の「最初の小さな実装単位」と同じ方針）。
- 経路レコード案：`{ kind: 'LM' | 'L1' | 'branch_path' | ..., edgeRefs: [...], lengthActualM, lengthEquivalentM | null, status: 'determined' | 'not_determinable' }`。相当長が未入力の経路は `not_determinable` とし、実長で代用して判定しない（C3参照）。
- LM は「室外機→最初の分岐の辺」ではない。LA と LB は別々の辺（または辺の区間）の和である。したがって LM の長さ・増径は、LA 辺と LB 辺をまたいで計算する必要がある。

### 未決事項 D1（最重要）：室外第一分岐と第一分岐の対応 — **決定済み（2026-10-26、ユーザー決定）**
- 図1の定義では LA は「室外第一分岐〜第一分岐」である。現行ツリーには室外機ノードと分岐ノードしかなく、「室外第一分岐」と「第一分岐」を区別する情報がない。
- `uxe3-segment-mapping.md` は LA を「室外機→最初の分岐の辺」と整理したが、これは図1の定義の簡略化であり、境界の定義がないことを同文書も認めている。**LA＝室外機→最初の分岐、と断定してはならない。**
- **決定（2026-10-26）**：候補（a）を規則とする。L1候補経路上で最初に現れる分岐ノードを「室外第一分岐」、その次の分岐ノードを「第一分岐」、さらに次の分岐ノードを次の分岐とする。室外機→最初の分岐の辺は LA ではなく室外機側接続配管 ℓA（ℓB・ℓC・LO を含む）である。
- **根拠**：図1（印刷 -4-）の拡大確認（2026-10-26）。室外第一分岐は ℓA・LO が合流する分岐管そのものであり、そこから右へ出る短い太管が LA、次の分岐管が第一分岐である。LM の寸法線は室外第一分岐から LB と LC の境目までを指し、LM＝LA＋LB と一致する。L2・L4 の寸法線も第一分岐を起点とする。表1の「各室外ユニットから室外第一分岐まで ≦10m」も、最初の分岐を室外第一分岐とする読み方と整合する。
- **留保**：この対応は図1の配置に基づく決定であり、メーカーが文言で明示した定義ではない。単体機では合流する継手が存在しないが、定義は組合せ機と同じ文言で書かれているため、単体機にも同じ規則を適用する。候補（b）ユーザー宣言・（c）公式ソフトの区間定義の確認は採用しない。
- **影響**：経路診断の LM候補・ΔL候補は、仮定Aに基づく候補から決定事項D1の規則に基づく区間になった（`assumption` フィールドは `rule` に変更）。D4（50m の起点と径ラダー）は 2026-10-27 にユーザー承認により決定したため、LM を使った自動増径（＊2・＊3）の適用は実装順序6に進める。ℓA ≦10m の判定は未実装であり、別途の対応とする。

## 2. C2 区間ごとの容量基準の分離

### 現状（engine.js）
- `selectThreePipeSize(outdoorKw)`（engine.js 246行目）は室外機容量だけを受け、12〜16HP を `outdoorKw <= 45.0` の同一分岐、18〜20HP を `outdoorKw <= 56.0` の同一分岐としている。`else` 分岐（24HP〜）は現行マスターの対応範囲外である。
- `processNodeSizing`（566行目〜）は、UXE3 の上流（室外機ノード、または電磁弁キット下流でない分岐ノード）から分岐・電磁弁キットへの辺に、室外機総容量 `outdoorCap` で3管径を選ぶ。子の `childKw`（下流合計容量）は算出しているが、上流3管の選定には使っていない。

## 3. C3 相当長モデル — L1相当長＞90m の判定根拠がない

### 現状
- PA-P900UXE3 の16ページ内に、継手・曲がりの相当長換算表は存在しない（検証報告 REPORT.md §3）。したがって現行ツリーの実長だけでは L1 の相当長を算出できない。
- 現行コードに相当長の入力・フィールドは存在しない。`totals.totalLength` は実長の合計である。

### 設計案
- 相当長は次のいずれかで与える。（a）システム単位でユーザーが L1 相当長を直接入力する（最も単純で監査しやすい）、（b）辺ごとに継手・曲がりの種別と数量を入力し、出典を明示した換算表で算出する。
- まず（a）を採用する。入力がない場合は L1 相当長を `not_determinable` とし、90m 判定を行わず警告を出す。**実長を相当長とみなして判定しない。**
- 境界は「90m を超える」（＞90m、＝90m は含まない）。境界テストは 90.0m（増径なし）と 90m 超（増径あり）を分ける。
- （b）に進む場合、換算表の出典（空調設備設計資料・P-SPEC 等の資料名・版・ページ）を `sourceKey` に記録し、表の適用型式・冷媒・世代を確認してから使う。出典不明の換算値は使わない。

### 未決事項 D3：相当長換算表の出典
- 別資料の特定が未完了。UXE3（R410A・2011年版）と換算表の適用版の対応を確認する必要がある。

## 4. C4 50m境界の分割表現 — 1本の辺を増径区間と標準径区間に分ける

### 公式条件（表1 脚注＊2・＊3）
- ＊2：L1 が 90m（相当長）を超える場合、主管 LM の吸込管・吐出管・液管を1ランク増径する（レデューサーは現地調達。表4および表7より選定）。
- ＊3：＊2以外の場合でも、LM の最大長が 50m を超える場合は、50m までの部分の主管サイズを吸込管・吐出管とも1ランク増径する（レデューサーは現地調達。50m を超える部分は表4より選定し、1ランク増径は表7より選定）。
- ＊2 と ＊3 は排他的である（＊3 の「＊2以外の場合でも」）。両方を重ねて適用してはならない。＊2 では液管も増径するが、＊3 では液管は増径しない。

### 現状（engine.js）
- BOM は辺ごとに全長を1つの径で加算する（`totals.liquidPipes[径] += len` 等）。1本の辺を途中で径を変えて分割する構造はない。異径継手（レデューサー）の BOM 項目もない。
- `sizeUpPipe` の径ラダーは `LIQUID_SIZES = [6.35, 9.52, 12.7, 15.88, 19.05]`、`GAS_SIZES = [9.52, 12.7, 15.88, 19.05, 22.2, 25.4, 28.58, 31.8, 38.1]`（engine.js 18〜20行目）である。表7の径リスト（REPORT.md §2 参考：6.35、9.52、12.7、15.88、19.05、22.22、25.4、28.58、31.8、38.1、41.28）とは一致しない。GAS_SIZES には 41.28 がなく、34.93 もない。表4・表5の 31.75 と表7・GAS_SIZES の 31.8 の表記ゆれもある。

### 設計案
- 分割レコード案：`{ edgeRef, segments: [{ fromM, toM, diameters: {liquid, discharge, suction}, kind: 'upsized' | 'standard' }] }`。分割後の各径の長さ合計が元の辺長と一致することを不変条件とし、テストで固定する（ゲート E の受入テストと同じ）。
- 境界の異径継手（レデューサー、現地調達）を BOM へ反映する。径が変わる境界ごとに1個、管種ごとに分けるかは BOM の表示設計で決める。
- 50m 境界は LM 経路上の位置で決まる。LM が複数辺にまたがる場合、50m の位置は辺の途中またはノード上になる。分割は経路位置で行い、辺単位に丸めない。
- 「1ランク」の径ラダーは表7のリストを正とする（D4決定、2026-10-27）。31.75／31.8 は同一管径の表記ゆれ、22.2 は 22.22 の誤記扱い。吸込 φ38.1 の1ランク上は 41.28 とする（38.1 で止めない）。

### 決定事項 D4：50m の起点と径ラダー — **決定済み（2026-10-27、ユーザー承認）**
- 50m は LM の室外機側の端（室外第一分岐）から測る。径ラダーは表7のリストを正とし、ガス管の上限は 41.28 とする（38.1 で止めない）。

### D4 推奨案（2026-10-27、ユーザー承認により決定）
- **50m の起点：室外第一分岐（LM の室外機側の端）から測ることを推奨する。** 根拠：(1) 脚注＊3 の原文（PDF p4）は「主管（LM）の最大長が、50mを超える場合は50mまでの部分」と LM の長さを測るもので、LM＝LA＋LB であり LA は室外第一分岐から始まる（D1決定・図1の LM 寸法線）。ℓA・LO は LM の一部ではないため、室外機本体からの計測は LM の定義と合わない。(2) 増径の意味（流量が最大の室外機側の圧損対策）からも、室外機側の最初の50m が自然である。留保：原文に起点の明記はなく、推論である。確実な確認にはメーカー照会（P-SPEC 等）が必要。
- **径ラダー：表7の径リストを正とする**（＊3「1ランクサイズアップは表7より選定」）。6.35、9.52、12.7、15.88、19.05、22.22、25.4、28.58、31.8、38.1、41.28。22.2 は 22.22 の誤記扱い（engine.js の GAS_SIZES は 22.2 となっており、実装時に 22.22 へ正す）。
- **31.75／31.8：同一管径の表記ゆれとみなす**（1-1/4インチ＝31.75mm、表7は 31.8 と丸めて表記）。増径のラダー上では表7の 31.8 を用い、表4・表5の基準径としては 31.75 を維持する。両者を別の径として扱わない。
- **ガス管の上限：38.1 で止めない。** 表7の次の径は 41.28 であり、＊2・＊3 とも「表7より選定」とあるため、基準径 38.1 からの1ランクアップは 41.28 とする。「ガス管はφ38.1まで」という記述は本PDF内には見当たらず、検索テキスト由来の未確認情報であるため根拠としない。留保：41.28 のガス管が UXE3 の実系統で使われるのは最大級（1350形相当）＋長配管のときに限られ、実例は稀。メーカー確認が望ましい。
- 2026-10-27 にユーザーが本推奨案を承認し、D4 は決定となった。実装順序4（50m分割レコード＋BOM）および順序6（＊2・＊3の適用）に進める。

## 5. C5 並列電磁弁キット — 224・280形室内機

### 公式条件（表6 脚注＊1、印刷 -5- のキット容量区分）
- 224・280形の室内ユニットを使用する場合、電磁弁キットは 160形を並列で使用し、配管は電磁弁キットの前後で分岐する。
- キット容量区分：160形は 5.6kW（超え）〜16.0kW（含む）、56形は 2.2kW（含む）〜5.6kW（含む）。容量範囲を超える場合は2個を並列に接続して使用する。

### 現状（engine.js）
- `processNodeSizing` は電磁弁キット1ノードにつき BOM へ1個を集計する（`totals.joints[node.modelNumber] += 1`）。
- `generateSolenoidKitModel` は下流容量と台数から CZ-P56HRV3 / CZ-P160HRV3（個別用）または CZ-P56HRG3 / CZ-P160HRG3（グループ用）を1品番だけ返す。並列の概念はない。224形（22.4kW）・280形（28.0kW）の室内機が下流にあっても、キットは1個として扱われる。
- キット品番の 5.6kW 境界（≦5.6 で 56形）は、公式の「56形は〜5.6kW（含む）」と数値上は一致するが、HRV3／HRG3 の使い分けと合わせて公式照合は未完了である。

### 設計案
- 並列は「キットの前後で分岐する」ため、ツリー（各ノードは親を1つだけ持つ）では単純な複製では表せない。候補：
  - （a）キットグループノード：並列ペアを1つの複合ノードとして表し、`parallelCount: 2` と内部分岐を持つ。BOM は 2個。辺の長さはグループ単位で1本として扱う。
  - （b）分岐ノードの下にキット2ノードを並べ、室内機側で合流ノードを新設する（合流ノード型の追加が必要）。
  - （c）キットノードに `parallel: true` フラグだけを持たせ、BOM 数量を2にする（前後の分岐配管は表せない）。
- 推奨は（a）。変更範囲がキット周辺に限定され、ツリー構造の前提（単一親）を壊さない。ただし並列間の配管長（前後の分岐から各キットまでの長さ）をどう入力・按分するかは未決事項 D5 とする。安易に「同じ長さを2本分」として BOM を2倍にしない。
- 224・280形以外の室内機で下流合計が 16.0kW を超える場合の並列条件も、公式の容量区分に沿って同じグループノードで扱えるか確認する。

### 未決事項 D5：並列キットの配管長と合流の表現
- 前後の分岐配管の長さ・径（表6の分岐管〜キット配管は室内機形式別）を、並列の2系統にどう割り当てるか。公式図の分岐形態の確認が必要。

## 6. C6 複数室外機の構造 — LO と組合せ機の分解

### 現状
- 現行マスターは 8〜20HP のみで、18HP は PA-P504UXE3（50.4kW）、20HP は PA-P560UXE3（56.0kW）として単一の室外機ノードで扱う（engine.js 81行目〜）。

### 設計案
- 組合せ機を室外機グループノードとして表し、構成ユニットを子ノードに持つ。構成ユニット間を LO 辺で接続し、バランス管 φ9.52（表4 脚注＊2）を別管種として持つ。

### 未決事項 D6：室外第一分岐の位置

## 7. C7 分岐継手の扱い — UXE3 では BOM に計上されない

### 現状（engine.js）
- `processNodeSizing` の末尾で、分岐ノードの継手（`jointModel`）を BOM へ集計するのは `seriesId !== 'fsv_uxe3'` の場合のみである（639行目）。UXE3 の分岐ノードは継手を計上されない。
- UXE3 の分岐継手が意図的に除外されているのか、未実装なのかは、コードにも文書にも根拠が残っていない。

### 設計案
- まず事実確認を行う。確認項目：UXE3 の分岐に使う継手の正式名称・品番（分岐管か、チーズ分か）、第一分岐と下流分岐で継手が異なるか、L3（現地調達によるチーズ分岐配管、最初のチーズから先端の密着部まで ≦2m）が継手 BOM に入るか。

- 継手が判明した場合は、区間種別ごとに継手の要否を決める（例：LA／LB の境界の分岐継手、分岐管〜キットの分岐、並列キットの前後分岐）。C4 のレデューサーとは別項目として BOM に載せる。

### 未決事項 D7：分岐継手の品番と要否

## 15. 実装記録：順序2・容量基準の配管と計算側の堅牢化（2026-10-26）

### 容量基準の配管
- `engine.js` に `selectPipeSizeForSegment(segmentKind, basis, isManualSizeUp)` を追加した。区間種別と容量基準を明示して管径を選定する入口であり、現行の `selectThreePipeSize`／`selectTwoPipeSize` へ振り分けるだけである。
- 区間種別は2種類のみ。`upstream_three_pipe`（室外機〜電磁弁キット間の3管、基準は室外機容量）と `downstream_two_pipe`（電磁弁キット下流の2管、基準は下流合計容量）。上流3管は LA／LB／LC〜LH を区別しない一括区分のままであり、区間別の表（表4／表5／表6）への切替えはゲート C・D を通過するまで行わない（D1 未決）。

- 不明な区間種別・容量基準の欠落は例外とする。容量の値が範囲外・非有限の場合は旧関数へ委譲する（else 分岐の最大径）。calculateSystem は従来どおり「UXE3対応容量外」の危険警告を出す。非有限容量をエラー返却に変える案は一度実装したが、既存テスト（非有限容量は警告で扱う）と衝突したため採用しなかった。

- **循環・共有ノードのガード**：`processNodeSizing` に循環・共有ノードのガードを追加した。循環はその接続先の計算を停止し危険警告、共有ノードは2回目を集計せず危険警告を出す。`getDownstreamCapacity`／`countIndoorUnitsDownstream` にも循環ガードを追加し、非数値の室内機容量は 0kW として扱う（文字列の容量が合計に混ざるのを防ぐ）。

§10 の順序5を実施した。C5（並列電磁弁キット）と C6（複数室外機）のグループノードを実装する。決定事項D1・D4（2026-10-26／2026-10-27、ユーザー承認）に基づく。

### 実装内容（C5・並列電磁弁キット）
- `getSolenoidKitParallelCount(node)` を追加した。下流合計が 160形キットの上限 16.0kW を超える場合に 2、ちょうど 16.0kW 以下の場合に 1 を返す。224形（22.4kW）・280形（28.0kW）の室内機1台でも、下流合計が 16.0kW を超えるため並列になる。
- `processNodeSizing` は、UXE3の電磁弁キットノードについて品番を変えず台数だけを並列数で計上する（`totals.joints[品番] += parallelCount`）。ノードには `parallelCount` と、並列の場合のみ `kitGroup`（`parallelCount`／`modelNumber`／`downstreamKw`／`indoorCount`／`internalBranch`）を注釈する。UXE3以外では従来どおり1個とし、注釈も付けない。
- `auditUxE3KitGroups(rootNode)` を追加した。ツリーを走査し、各キットノードについて品番・下流合計・室内機台数・並列数・内部分岐（`branches: 2`、長さの割り当ては `not_determinable`）を記録する。`calculateSystem` は `fsv_uxe3` の場合のみ戻り値に `kitGroups` を追加した（他シリーズでは `null`）。
- 並列グループを検出した場合は警告パネルへ情報警告（`【並列電磁弁キット】`）を出す。配管長はグループ単位の辺で1本分のみ集計し、同じ長さを2本分として数えない（ノードを複製しないため、構造上2倍にならない）。
- 下流合計が 32.0kW（160形×2の上限）を超える場合は、台数は2のままとし、危険警告を出す。3個以上の並列規則は定義していない。

### 実装内容（C6・複数室外機）
- `OUTDOOR_GROUP_COMPOSITION` を追加した。PA-P504UXE3＝CU-P280UXE3＋CU-P224UXE3、PA-P560UXE3＝CU-P280UXE3×2（仕様書で確認済み）。
- `auditUxE3OutdoorGroups(rootNode)` を追加した。室外機容量が 50.4kW／56.0kW の場合に室外機グループとして分解する。LO の径は表4（`selectThreePipeSize`）で組合せ合計容量を基準として選定し、仕様書の接続管径（吸込 φ28.58／吐出 φ22.22／液 φ15.88）と一致する。LO の長さはルートの `loLengthM`（室外接続主配管の実長）で与える。未入力の場合は判定不可とし、実長で代用しない。不正な値（非数値・非有限・負数）の場合は危険警告を出す。バランス管 φ9.52 の長さは LO と同じ長さとする（同じ2台の間を併走する配管である）。
- `applyUxE3OutdoorGroupToTotals(totals, outdoorGroups)` を追加した。LO の3管分の長さとバランス管の長さを BOM へ加算する（純粋な加算であり、基準径からの移動ではない）。バランス管用に `totals` へ `balancePipes`（径→長さ）の集計を追加した。`totalLength` は変えない（LO はグループ内部の辺であり、ツリーの辺ではないため）。
- `calculateSystem` は `fsv_uxe3` の場合のみ戻り値に `outdoorGroups` を追加した（他シリーズでは `null`）。LO・バランス管の長さが確定した場合のみ BOM へ反映し、その旨を情報警告（`【組合せ室外機】`）で出す。LO の長さが未入力の場合は警告を出さない（実装順序3の既定と同じ）。
- グループから最初の分岐ノードへの辺は、決定事項D1の規則により室外機側接続配管 ℓA として扱う（`outdoorGroups.firstBranchEdge: 'lA'`）。経路診断（`pathAudit`）の LM 候補は変わらず、LA は最初の分岐ノードから始まる。対応範囲は 8〜20HP のまま。`maxIndoorUnits: 52` と PA-P900UXE3 p3 の40台との差異は変更していない（未解決のまま）。

### 採用した保守的な読み方・未決事項として残すもの
- **D5（並列キットの配管長）は引き続き未決。** 内部分岐の長さ・径の割り当ては `not_determinable` とし、グループ単位の辺長のみを集計する。同じ長さを2本分として BOM を2倍にすることはしない。
- **D6（LO と LA の境界）は引き続き未決。** 室外第一分岐が構成ユニットの合流点かその先の分岐かは決まっていない。グループから最初の分岐ノードへの辺を ℓA として扱うことは D1 の規則によるもので、D6 の決定ではない。
- LO の径の基準は組合せ合計容量とした。表1 脚注＊1の「先端に接続される室外ユニットの合計容量」を、2台組合せの LO が合流点側で運ぶ合計流量と読んだものであり、仕様書の接続管径と一致することを確認した。3台以上の組合せ（26HP以上、対応範囲外）では LO 辺ごとの先端合計が異なるため、この読み方は2台組合せに限る。
- LO の吐出径はエンジンの既存値 22.2 で記録する（仕様書の表記は 22.22）。表記ゆれ D2（22.2 は 22.22 の誤記、同一管）であり、LM 辺の基準径と同じキーで集計するため、別の径として扱わない。22.22 のキーで集計すると同じ管径が2つのキーに分かれるため、採用しない。
- バランス管の表示は UI 側の別途の対応とする。`totals.balancePipes` は結果に含まれるが、ui.js は現行の集計項目（液管・ガス管・吸入／吐出ガス管・継手）のみを表示する。
- `node.parallelCount`／`node.kitGroup` の注釈は入力ツリーへの変更であるが、既存の注釈（`modelNumber`／`pipes`／`pipeSizeText`）と同じ扱いであり、計算の入力値（容量・長さ）は変えない。
- 下流合計が 32.0kW を超えるキットノードの扱い（危険警告、台数2のまま）は、160形×2の上限を超える場合の暫定の扱いである。3個以上の並列規則は公式確認なしに作らない。
